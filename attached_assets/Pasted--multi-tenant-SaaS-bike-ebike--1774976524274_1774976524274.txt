Теперь нужно реализовать следующий слой для новой multi-tenant SaaS-платформы аренды bike / ebike / scooter / escooter:

1. public website foundation
2. public company page /p/:slug
3. inquiry / lead flow
4. B2B request flow
5. company branding/settings
6. notifications foundation
7. feature flags / enabled modules foundation

Считать, что уже готовы:
- schema and migrations for core modules
- auth / RBAC / memberships
- CRUD foundation for branches / stations / clients / assets / rentals / blacklist
- payments / deposits / incidents / maintenance / reports foundation
- audit service
- tenant-safe repositories
- Zod validation foundation

Важно:
- сейчас не делать full frontend landing production-polish
- сначала сделать clean backend foundation + minimal public endpoints + data model + internal workflows
- public flows должны быть безопасны, rate-limited и tenant-aware
- company public visibility должна управляться настройками компании
- не делай car-specific naming
- не делай пока telemetry/mobile/device integration

---

# 1. Общая цель этапа

Нужно, чтобы каждая компания платформы могла:
- иметь публичную страницу по slug
- показывать бренд, описание, контакты, города/станции, доступный транспорт
- принимать публичные заявки на аренду
- принимать B2B заявки от компаний
- управлять branding и public settings из кабинета
- получать базовые internal notifications по событиям

# 3. Public company page

## 3.1. URL pattern
Публичная страница компании:
- GET /public/companies/:slug
или
- GET /p/:slug

Выбери один pattern и используй consistently.
Если backend и frontend разделены, backend может отдавать JSON API для public page.

## 3.2. Что должна возвращать public page
Если publicEnabled = true, вернуть:
- company public identity
- title / description
- logo / cover
- contact info
- public city / address
- visible stations, если включено
- visible assets summary, если включено
- pricing summary, если включено
- inquiry form availability
- B2B form availability

## 3.3. Public assets visibility
Публично можно показывать только assets, которые:
- belong to company
- isPublic = true
- not archived
- status in allowed visible statuses (например available / reserved maybe, depending on policy)

Сделай clean policy helper для public visibility.

## 3.4. Public stations visibility
Показывать только станции компании, которые:
- не archived
- имеют public visibility, если решишь ввести такой флаг
- либо по умолчанию все active stations, если publicShowStations = true

# 6. Inquiry / lead flow (B2C)

## 6.1. Назначение
Публичный пользователь может оставить заявку на аренду.

Это не должно автоматически создавать active rental.
Это lead / inquiry intake flow.

## 6.2. Нужна отдельная сущность
Создай foundation table, например:
- inquiries

Поля:
- id
- companyId
- branchId nullable
- stationId nullable
- source = public_inquiry
- status
- fullName
- phone
- email nullable
- assetType nullable
- preferredAssetId nullable
- requestedStartAt nullable
- requestedEndAt nullable
- message nullable
- blacklistCheckResult jsonb nullable
- createdAt
- updatedAt
- processedByUserId nullable
- convertedClientId nullable
- convertedRentalId nullable

## 6.3. Inquiry statuses
Поддержи:
- new
- in_review
- contacted
- converted
- rejected
- spam
- archived

## 6.4. Endpoint
Сделай публичный endpoint:
- POST /public/companies/:slug/inquiries

И внутренние:
- GET /inquiries
- GET /inquiries/:id
- PATCH /inquiries/:id
- POST /inquiries/:id/mark-contacted
- POST /inquiries/:id/convert-to-client
- POST /inquiries/:id/convert-to-rental-draft
- POST /inquiries/:id/reject

## 6.5. Business rules
При создании inquiry:
- company must be publicEnabled
- inquiry form must be enabled
- slug must resolve to active company
- normalize phone/email
- perform blacklist pre-check and save result
- do not auto-block submission unless it is clearly hard-blocked and policy says so
- rate limit required
- audit for internal processing actions only

## 6.6. Conversion flow
Нужны helpers:
- convert inquiry -> client
- optionally create rental draft from inquiry
Не создавать дубли без проверки по phone/email/document when possible.

# 13. Business rules and scope rules

## 13.1. Inquiries
- belong to company
- optionally linked to branch/station
- processed only by tenant users with proper permissions
- visible only inside tenant

## 13.2. B2B requests
- belong to company
- internal processing only by tenant users with proper permissions

## 13.3. Notifications
- tenant-safe
- only target users can read their notifications
- company users cannot read notifications of another user unless you intentionally add admin visibility later; for now keep it simple and private per user

## 13.4. Public page
- accessible only if company publicEnabled
- hidden if company blocked/canceled or public disabled
- do not leak internal IDs and internal operational data
