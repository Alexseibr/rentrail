# 1. Testing strategy

## 1.1. Нужно покрыть 4 уровня
Сделай testing foundation для:
1. unit tests
2. service/integration tests
3. API tests
4. smoke/e2e foundation for critical flows

## 1.2. Приоритет тестов
Сначала покрыть самое рискованное:
- auth / refresh / sessions
- RBAC / tenant isolation
- company/branch guards
- assets / rentals workflow
- blacklist effective decision
- payments/deposits lifecycle
- incidents / maintenance transitions
- telemetry ingest auth and resolution
- inquiry conversion flows

## 1.3. Testing stack
Выбери clean stack, например:
- Vitest or Jest for unit/integration
- Supertest for API tests
- test database setup for PostgreSQL
- optional Playwright foundation for web smoke tests
- optional Expo/mobile tests only as light foundation for now

Если выбираешь конкретный стек, опиши почему.

# 4. API tests

## 4.1. Нужны end-to-end API tests через HTTP
Покрой ключевые routes:
- /auth/*
- /branches
- /stations
- /clients
- /assets
- /rentals workflow actions
- /blacklist/check
- /payments / deposits workflow actions
- /incidents / maintenance workflow actions
- /public/companies/:slug
- /public inquiries / b2b requests
- /telemetry/ingest
- /notifications
- /reports summary endpoints

## 4.2. Важные API test cases
Покрой обязательно:
- unauthorized access denied
- wrong company context denied
- wrong branch context denied
- branch-scoped user cannot access foreign branch data
- blacklisted client cannot start blocked rental
- duplicate QR/serial constraints handled
- offline/retired/lost asset cannot be rented incorrectly
- refund > payment amount rejected
- deposit release+forfeit > total rejected
- public page disabled returns proper error/not found
- public inquiry rate-limited behavior if feasible to test

---

# 5. Multi-tenant isolation test pack

## 5.1. Очень важный блок
Сделай отдельный suite именно для tenant isolation.

Покрой:
- user from company A cannot read company B assets
- user from company A cannot mutate company B rentals
- branch-scoped user in branch X cannot access branch Y if not allowed
- company-level admin can access all company branches
- superAdmin override works intentionally
- public slug endpoints do not leak non-public company data
- telemetry ingest cannot spoof company by payload alone

## 5.2. Это should be explicit
Не размазывай эти тесты случайно по другим suite.
Сделай отдельный visible test group for tenant isolation.
