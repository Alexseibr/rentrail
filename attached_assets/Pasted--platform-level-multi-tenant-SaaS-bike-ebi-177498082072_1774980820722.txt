Теперь нужно реализовать platform-level слой для новой multi-tenant SaaS-платформы аренды bike / ebike / scooter / escooter.

Считать, что уже готовы:
- backend foundation
- tenant core modules
- finance / incidents / maintenance / reports
- public pages / inquiries / b2b requests / notifications / feature flags
- telemetry / devices / batteries / geofences / commands foundation
- web admin panel tenant-side
- mobile operator app
- scanner / uploads / push / offline queue
- QA / tests / demo / CI / release readiness

## Цель этапа
Реализовать platform-level возможности для владельца SaaS:
1. super-admin backend and UI
2. SaaS billing admin UI and workflows
3. tenant moderation / approvals / blocking
4. platform global blacklist management
5. white-label management foundation
6. platform analytics and diagnostics
7. support/admin operational tools

Важно:
- это platform scope, а не tenant scope
- superAdmin должен работать отдельно от company roles
- tenant data visibility должна быть controlled and auditable
- не делай хаотичную “панель бога”, нужен clean governance layer

# 1. Platform scope and access model

## 1.1. Platform roles
Нужно явно поддержать platform-level roles:
- superAdmin
- platformAdmin
- platformSupport
- platformFinance
- platformRisk

Если в текущей системе только `superAdmin`, расширь модель cleanly.
Можно через platform_roles / platform_permissions или через отдельный access layer.
Выбери clean решение и объясни.

## 1.2. Rule
Platform roles не должны смешиваться с tenant company memberships.
User может иметь:
- platform-level role
- tenant memberships
одновременно, но это разные scopes.

## 1.3. Auditing
Все platform-level sensitive actions должны логироваться отдельно и подробно:
- кто смотрел tenant
- кто изменил billing/subscription
- кто заблокировал tenant
- кто менял white-label settings
- кто добавил global blacklist entry
