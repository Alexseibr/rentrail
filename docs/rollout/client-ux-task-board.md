# Client UX Task Board (что делаем прямо сейчас)

## Сегодня (Day 0)

### 1) Создать задачи в трекере

- [ ] UX-01 Онбординг 3 шага
- [ ] UX-02 Прозрачная цена до старта
- [ ] UX-03 SOS в активной аренде
- [ ] UX-04 Упрощённое завершение аренды
- [ ] UX-05 Тексты ошибок + retry

Шаблон задачи:

- **Problem:** какой пользовательский барьер снимаем
- **Scope:** какие экраны/API затрагиваем
- **Acceptance Criteria:** что должно работать
- **Metric:** на какую метрику влияем
- **Owner / ETA:** ответственный и срок

### 2) Назначить ответственных

- Product owner: приоритизация и KPI
- UX/UI designer: макеты и тексты
- Mobile engineer: клиентские экраны
- Backend engineer: API/валидации/события
- QA engineer: e2e happy+edge сценарии

### 3) Провести 45-мин kickoff

Повестка:

1. Проверить baseline KPI
2. Подтвердить scope P0
3. Утвердить DoD
4. Зафиксировать дату rollout 10% и 100%

## Эта неделя

### Delivery-последовательность

1. Онбординг + прозрачная цена
2. SOS-flow
3. Упрощённое завершение аренды
4. Ошибки/ретраи/офлайн-состояния

### Релизная стратегия

- День 1–3: internal QA
- День 4: rollout 10%
- День 5: rollout 50%
- День 6–7: rollout 100%

## Acceptance checklist перед rollout 100%

- [ ] Старт аренды: не более 2 тапов после выбора актива
- [ ] Завершение аренды: не более 3 тапов + 1 фото
- [ ] Показ цены до старта обязателен
- [ ] SOS-кнопка доступна из активной аренды всегда
- [ ] Ошибки сети/GPS/замка имеют понятные тексты
- [ ] Все критические сценарии пройдены на iOS/Android

## Что смотрим через 7 дней после rollout

- Conversion to first ride
- TTFR
- End-rental success rate
- Support tickets / 100 rides
- CSAT после завершения поездки

Решение по итогу 7 дней:

- Если KPI достигнуты — идём в P1 (история поездок, персональные подсказки).
- Если KPI не достигнуты — ещё 1 итерация P0 с фокусом на самый большой drop-off.
