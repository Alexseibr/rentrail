# Client UX — что далее

## Цель ближайших 14 дней

Запустить P0-улучшения клиентского флоу так, чтобы:

- уменьшить ошибки завершения аренды;
- снизить обращения в поддержку;
- повысить конверсию в первую успешную поездку.

## План по дням

### День 1

- Снять baseline-метрики: conversion to first ride, TTFR, drop-off по шагам, support/100 поездок.
- Выгрузить топ-10 обращений клиентов за последние 30 дней.

### День 2

- Финализировать UX-тексты для:
  - старта аренды;
  - завершения аренды;
  - ошибок сети/GPS/замка.
- Утвердить макеты экранов: Onboarding, Start rental, Active rental (SOS), End rental.

### Дни 3–5

- Реализовать онбординг в 3 шага.
- Внедрить прозрачный блок цены до старта (тариф/депозит/возможные списания).
- Добавить SOS-кнопку с пресетами проблем.

### Дни 6–8

- Реализовать упрощённое завершение аренды:
  - проверка geofence;
  - обязательное фото;
  - подтверждение финальной суммы.
- Добавить дружелюбные сообщения ошибок и retry-сценарии.

### Дни 9–10

- QA по критическим сценариям (happy path + edge cases).
- Пилот на части клиентов (например, 10–20% трафика).

### Дни 11–14

- Выкатка на 100% клиентов.
- Сравнение KPI c baseline.
- Формирование задач P1 на следующий спринт.

## Технический backlog (P0)

| ID    | Задача                              | Owner           | Оценка | Зависимости                 | KPI                      |
| ----- | ----------------------------------- | --------------- | -----: | --------------------------- | ------------------------ |
| UX-01 | Онбординг 3 шага после логина       | FE Mobile       |     2d | Auth, client mode           | conversion to first ride |
| UX-02 | Блок прозрачной стоимости до старта | FE Mobile + API |     2d | rentals, payments, deposits | support/payment tickets  |
| UX-03 | SOS-кнопка в активной аренде        | FE Mobile + API |     2d | service-requests, incidents | first response time      |
| UX-04 | Упрощённое завершение аренды        | FE Mobile + API |     3d | geofences, attachments      | end-rental success rate  |
| UX-05 | Тексты ошибок и retry               | FE Mobile       |     1d | telemetry/error mapping     | drop-off reduction       |

## Definition of Done для P0

- Все 5 задач UX-01…UX-05 в проде.
- Нет blocker-дефектов по критическим сценариям.
- Изменения метрик относительно baseline:
  - conversion to first ride: +10% и более;
  - ошибки завершения аренды: -20% и более;
  - support tickets по оплате: -30% и более.

## Риски и меры

- Риск: неготовность API-ответов для прозрачной цены.
  - Мера: временный fallback с расчётом диапазона и дисклеймером.
- Риск: рост ложных SOS-обращений.
  - Мера: пресеты + обязательная категория проблемы.
- Риск: падение UX из-за слабой сети.
  - Мера: offline/error состояния и явная кнопка повторной отправки.
