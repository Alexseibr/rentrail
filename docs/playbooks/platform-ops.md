# Platform Operations Playbook

## 1. Tenant Approval

### When

A new company signup arrives with status `pending`.

### Steps

1. Review company details in platform admin → Companies → click on pending company
2. Verify business legitimacy:
   - Company name and legal name make sense
   - Email domain matches business
   - Country and currency are valid
3. Check for duplicate signups (search by email, slug, or name)
4. Decision:
   - **Approve**: Click "Approve" → enter reason code `initial_approval` → confirm
   - **Reject**: Click "Block" → enter reason code `failed_verification` with explanation → confirm
5. If approved:
   - Assign appropriate plan via "Set Plan"
   - Create subscription record
   - Send welcome email with onboarding link
6. Log decision in platform audit trail (automatic)

### Escalation

- If unsure about legitimacy → escalate to platform super-admin
- If company requests enterprise plan → schedule qualification call

## 2. Billing Issue Resolution

### Common Scenarios

#### Invoice Dispute

1. Navigate to company detail → Billing tab
2. Locate disputed invoice
3. Review invoice details (amount, period, plan)
4. Cross-reference with subscription record
5. Resolution options:
   - **Correct charge**: Explain billing to tenant via email
   - **Overcharge**: Void invoice → create corrected invoice
   - **Duplicate**: Void duplicate invoice
6. Document resolution in audit trail

#### Payment Not Received

1. Check invoice status (`issued` and past due date)
2. Timeline:
   - Day 1–7: Automatic reminder (if configured)
   - Day 7: Manual email reminder to billing contact
   - Day 14: Phone call to billing contact
   - Day 21: Escalate — consider suspending access
   - Day 30: Final notice — suspend account
3. If payment received: Update invoice status to `paid`
4. If disputed: Follow Invoice Dispute flow above

#### Subscription Change Request

1. Tenant requests plan upgrade/downgrade
2. Review current usage against new plan limits
3. If downgrade and over limits: inform tenant they must reduce usage first
4. Apply plan change via "Set Plan" on company detail
5. Prorate billing:
   - Upgrade: Charge difference for remaining period
   - Downgrade: Credit remaining difference to next invoice
6. Confirm change with tenant

## 3. Blocked Tenant Handling

### Block Decision

Reasons to block a tenant:

- Terms of service violation
- Fraudulent activity detected
- Sustained non-payment (30+ days)
- Legal/compliance requirement

### Block Procedure

1. Navigate to company detail in platform admin
2. Document the reason thoroughly (this is logged permanently)
3. Click "Block" → enter:
   - Reason code: `tos_violation`, `fraud`, `non_payment`, `legal_compliance`
   - Reason text: Detailed explanation
4. System sets company status to `blocked`
5. Blocked tenant effects:
   - Staff cannot create new rentals
   - Existing active rentals continue but no new ones
   - Platform admin access retained for data export
   - Public pages disabled
6. Notify tenant via email with:
   - Reason for blocking
   - Steps to resolve (if resolvable)
   - Data export instructions
   - Appeal process

### Unblock Procedure

1. Verify the blocking reason has been resolved
2. Navigate to company detail
3. Click "Unblock" → enter:
   - Reason code: `issue_resolved`
   - Reason text: Explanation of resolution
4. Verify subscription and billing are current
5. Notify tenant of reinstatement

## 4. Escalation Matrix

| Severity                              | Response Time  | Resolver         | Escalate To      |
| ------------------------------------- | -------------- | ---------------- | ---------------- |
| SEV-1: Platform down                  | 15 minutes     | On-call engineer | CTO              |
| SEV-2: Feature broken for all tenants | 1 hour         | Engineering team | Lead engineer    |
| SEV-3: Feature broken for one tenant  | 4 hours        | Support engineer | Engineering team |
| Billing dispute                       | 1 business day | Ops team         | Finance lead     |
| Security incident                     | 30 minutes     | On-call engineer | CTO + legal      |
| Legal/compliance                      | 1 business day | Ops team         | Legal counsel    |

### Escalation Procedure

1. Assess severity based on matrix above
2. Create incident record (see `incident-rollback-plan.md`)
3. Notify appropriate resolver
4. If not resolved within response time → escalate to next level
5. Keep affected tenants informed (use communication templates)
6. Post-incident: conduct review within 48 hours

## 5. Import Failure Resolution

### Diagnosis

1. Review import error report (generated by import process)
2. Categorize failures:
   - **Validation errors**: Bad data format, missing required fields
   - **Reference errors**: Branch/station not found
   - **Duplicate errors**: Entity already exists

### Resolution by Type

#### Validation Errors

1. Share error report with tenant
2. Ask tenant to fix source data
3. Re-import corrected rows only (safe due to dedup)

#### Reference Errors

1. Check if referenced branch/station exists
2. If name mismatch: correct CSV or create missing entity
3. Re-import affected rows

#### Duplicate Errors

1. These are usually safe — rows are skipped
2. Verify the existing entity matches expected data
3. If data differs: manually update or delete existing, then re-import

### Escalation

- If > 20% of rows fail: pause import, investigate root cause
- If data corruption suspected: stop all imports, notify engineering
